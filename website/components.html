# shipped components

componentlanguagepurpose
corenimconversation loop, supervisor, catalog, dispatch — and the context-window admission guard before every provider request; the human owns two per-conversation controls set through the session call and exposed as /approvals (the gate mode: ask or auto, granting loudly) and /limit (soft rounds/tokens/seconds budgets where reaching one asks "keep going?" instead of ending the turn), persisted in the conversation header; a session call arriving mid-turn is refused at once with busy instead of hanging; session {export: true} dumps the exact request the next turn would send (messages, allowlist-filtered tool schemas, model, provider, reasoning_effort) with no user message, LLM call or store write, and a timed-out or cancelled tool call keeps its partial output as an explicit error instead of a silent success
sessionnimone conversation = one process — an ephemeral per-conversation runner that resumes from the store; killing one loses only the in-flight turn
bashnimshell access as a tool — approval-gated, process-tree cancellation on stopped turns, oversized output spilled to disk and paged with read
buildernimcompiles agent-written Nim/Go/TypeScript source → binary — dependencies are declared by the source, never by the build call: a Go build resolves its imports with go mod tidy, a TS build scans the entrypoint's imports after the base install and npm-installs the external packages (the resolved ranges land in the generated package.json, and the reply lists them under deps)
storenim/godocument store over the bus (rev-based optimistic concurrency) — swappable engines behind one contract: SQLite (default, var/store.db), barrel and TiDB/MySQL, picked with NIF_STORE_BACKEND; list is a page (1000-item cap) returning hasMore + a nextAfter cursor, and core pages its full-kind reads automatically; a harness with un-migrated var/barrel-db history refuses to boot — niffler-store-migrate moves roots between engines offline (any engine pair, --scan/--all/--dry-run)
pluginsnimcomponent ecosystem: topic search, niffler.json packages, install/update/remove — always built from source; /plugins//plugins-search//plugins-install//plugins-update//plugins-remove slash commands namespaced by component name; tag resolution falls back to the repo's tags when it publishes no releases, and a branch-pinned install updates along its branch instead of being repointed at a release tag; TypeScript packages install too — the manifest reader accepts lang: "ts", and the entry builds through the builder and spawns like any other component
skillsnimAgent Skills discovery, progressive-disclosure loading, resources, managed install/remove, and skill_audit (unmerged on-disk inventory); the bundled self-knowledge set is also baked into the binary as a last-resort fallback (NIF_SKILLS_BUNDLED_DIR relocates it; baked entries report dir (baked))
systempromptnimthe conversation constitution as a component — session runners ask svc.systemprompt.call once per conversation; replace it to replace the prompt. Components and plugins contribute prompt fragments through the hidden prompt_hint tool — named slots (tool_usage, efficient_tools, after_instructions) rendered in deterministic order inside <prompt_slot> blocks for new conversations, never rewriting a frozen prompt — and instructions load lazily: AGENTS.local.md joins the shadow chain, and reading into a monorepo subtree injects that subtree's rules once per session in the tool result instead of the system prefix
recallnimthe on-demand context_recall resolver — pruned and spilled content is replaced by references, and this component resolves them: canonical messages, promoted spill documents and the current durable compaction checkpoint; every prune/spill notice names its ref verbatim, and mode: search greps the conversation's whole canonical history — trimmed and compacted-away messages included. On demand, never hidden: the model reaches it through discover + invoke, so the notices' advice is actionable
compactionnimthe replaceable context summarizer — long turns survive their own context: before every provider request core prices the call in the provider's own token scale and, at the pressure line, runs a deterministic ladder (lossless tool-result prune → summarizing compactor → whole-turn trim → explicit context-recovery-required) instead of ever sending an over-window request; durable trim records its watermark so replay is restart-safe, and a normalized provider overflow 400 gets one receipt-backed recovery attempt before it becomes terminal; a manual /compact reports the precise decline or failure reason instead of a generic no-cut message, and the auxiliary summary inherits the conversation's resolved provider/model rather than following a later global switch. This component is the default contract-v1 compaction_propose implementation (NIF_COMPACTION_TOOL selects another): it verifies the runner's paged snapshot, chooses a permitted cut and drafts a checkpoint candidate — the runner alone validates and commits the context_projection, canonical messages stay immutable, and any contract-v1 implementation can be proved against the contract with make test-conformance
fetchnimbounded HTTP(S) retrieval with methods/headers/body, Trafilatura-first HTML extraction, pure-Nim fallback, and large-result file spill. Egress is fail-closed: the host is resolved up front and loopback, private, link-local, carrier-grade NAT, multicast and unspecified addresses are refused (IPv4-mapped IPv6 normalized), as are localhost/.localhost/.local/.internal hostnames, URLs with embedded credentials, and DNS failures; redirects are re-validated hop-by-hop, capped at five and http(s) only. NIF_FETCH_ALLOW_PRIVATE=1 restores loopback access for trusted local development
editnimthe file tools — read (a single path, or the canonical reads array batching up to 12 files/ranges in one call, per-item errors, pageable; a whole read of a large file with a language server for its type returns the lsp symbol outline instead — window with offset/limit, or offset: 1 to read whole anyway), exact-match edit with a guarded fallback cascade, atomic write, single-level undo_last_edit; an unchanged full re-read returns a compact [unchanged] marker instead of re-dumping bytes (force or an offset/limit window opts out), edit refuses with E_STALE when the file changed since this conversation last saw it — and a re-read that observes different bytes persists the digest correction, so stale state can't survive a restart — and seen-state is tracked per (session, file); successful edits return a compact change preview (removed/added lines with context, explicitly truncated when large); mutations approval-gated
lspnimlanguage-server seam — one lsp tool (diagnostics without a test run, documentSymbol — the file outline, workspaceSymbol — repo-wide fuzzy symbol search, goToDefinition, findReferences, goToImplementation, hover) over any configured stdio language server (gopls, nimtortoise, typescript-language-server, pyright, rust-analyzer, clangd, bash-language-server, jdtls, csharp-ls by default); the registry is data ($XDG_CONFIG_HOME/niffler-lsp/servers.json) — adding a language is a config entry or an approval-gated lsp_registry add the agent makes itself, never code; make install-lsp installs the default servers per language and core warms them by census on workspace open; read-only lsp_servers lists the merged registry, /lsp in niffler-tui browses and edits it
repomapnimthe ranked workspace map (the aider repomap port) — the load-bearing files and their key definitions in ~1KB, built from a tree-sitter + native-Nim tags graph with personalized PageRank; repo_map is onDemand and read-effect: the model asks, nothing is injected. The workspace-open auto-append (one append-only entry per new conversation) is opt-in via NIF_REPOMAP_AUTOAPPEND=1 — off by default, since the A/Bs showed a token tax with no accuracy gain — and gated even when opted in: workspaces under the census floor (NIF_REPOMAP_MIN_CENSUS, default 50) are never mapped and a stub map (byte/symbol/file thresholds) is never injected, with withheld maps logged. Cache: var/repomap-tags/; an absent component means no map and nothing else changes
processesnimbackground processes with an owner — bash's run_in_background flag forwards to process_start (detached, own process group, spool files under var/processes/); process_poll drains incremental output, process_kill stops the group, process_list shows the registry with started_at; children are process-group leaders and registry.json drives a boot sweep against orphans — and a finished child tells its conversation: an exit notice (kind: "process-exited", the same lane subagent settlement notices use) is folded in as append-only history pointing at the spool ("ran 412s, 8123 bytes of output — read it with process_poll"); the component reaps children on the SDK's onIdle tick, so an exit is noticed without anyone polling
grepnimripgrep-backed content search (grep — in the default direct set, line- and 32KB byte-capped output) and sorted repository file listing (files — on demand), with exact truncation markers
gitnimread-only repo inspection — status/diff/log/show/blame, approval-free, fixed argv, path-scoped to the harness root; review_receipt — a local diff-fingerprint write/check pair for pre-push review handoff
observenimlive bus introspection — subject discovery, listen probes, request/reply traces, monitoring
logfilenimdurable JSONL sink for ev.log.* — rotating logs, bounded search, retention
hooksnimoperator shell commands on selected bus events (ev.session.*.turn, ev.log.>) — payload as JSON on stdin, observe-only, env-configured, off by default
modelsgomodels.dev provider/model catalog over the bus — offline seed, cached refresh, x-models-source plugin patches
providergostore-backed LLM provider registry — add/list/switch/active/remove/export/import, live backend switching, subscription OAuth logins with transparent token refresh; provider_models probes the provider's own /models for live model ids
llmgostreaming chat adapter — OpenAI-compatible Chat Completions by default (DeepSeek), plus the OpenAI Codex (ChatGPT OAuth) Responses and Anthropic Messages protocols — live ev.llm.token deltas, reasoning tokens, per-call cancellation; retries split failure budgets by kind — a 429 carrying Retry-After sleeps exactly the server-directed wait (capped, unbounded attempts), stream timeouts and connect refusals get their own bounded budgets (NIF_LLM_MAX_STREAM_RETRIES/NIF_LLM_MAX_CONNECT_RETRIES, default 2), and permanent markers (auth, quota, bad request) fail fast
mcpgoexternal MCP servers (Model Context Protocol) as bus components — store-backed registry with approval-gated mcp_add/mcp_edit/mcp_remove (every add/edit validated through one real connect), mcp_search over the official MCP Registry, and ${ENV} secret references resolved from the harness environment at connect time so tokens stay out of the store; a server's tools become ordinary catalog tools reachable through discover + invoke; a server configured expose: direct that publishes more than NIF_MCP_DIRECT_THRESHOLD tools (default 10) defers them to on-demand discovery instead of flooding the tool prompt
mcp-bridgegoone supervised process per MCP server (official Go SDK; stdio / streamable HTTP / SSE) — lazy sessions that idle out, a stdio guard so servers never outlive the harness, mid-flight cancellation, tool-contract drift persisted + bridge restarted so discovery stays truthful, prompts as slash commands, resources as one read tool, results over 64 KiB spilled to files
fabricnimprogrammable tool calling — the LLM writes a Nim program that owns the intra-turn control flow; each program is compiled to a native guest process (content-addressed binary cache, structured fabricguest SDK, on-demand fabric_help reference) and is stopped within seconds when its turn is cancelled; typed wrappers with catalog pinning, a named program library, host-backed batch calls, approval manifests, and correlated ev.fabric.* lifecycle events — plus run-tested worked examples that ship with the component
agentnimsubagent sessions — synchronous agent_run delegates to a child runner with fresh context; durable background jobs (agent_spawn/status/wait/stop/steer) survive restarts; a child is a session with memory: agent_run/agent_spawn {session} give an existing child another turn (append-only history, durable lineage authorization, busy-vs-queue semantics, an activation ledger, close: true retirement) and fork: true | {lastK} | {maxChars} seeds a fresh child with the caller's completed turns; a fresh child without an explicit model inherits the parent's effective model, or takes modelTier: weak | medium | strong clamped to the parent's tier; delegation depth is capped (NIF_AGENT_MAX_DEPTH, default 1 — subagents cannot spawn subagents) and nested calls run on id-keyed leases with per-call deadlines, so parallel session-context dispatch is safe; finished children reach the parent as settlement notices (a pointer to the byte-identical reply held by agent_status) without polling, agent_list is the derived child roster, steering an idle child queues as durable parent-mail for its next turn, and agent_ask returns a child's answer; idle runners retire on their own
expertnimthe advisory peer — follows one or more working sessions concurrently, LLM-judges bounded per-session observations (the judge prefix embeds the bundled niffler-tools/niffler-fabric/niffler-harness skills), delivers high-confidence steer as a marked message; silent by default, fail-closed
dialogbasha component in pure bash — dialog_show/dialog_ask desktop dialogs (zenity → notify-send → log fallback) spoken with only the nats CLI + jq, no SDK, no compile step
clinimdrive the harness from a script: catalog/wait/call/install — the CI front door for plugin repos; installs confirm against core's accepted catalog, not raw registration announcements
consolenimbus viewer — renders every envelope on stdout (follow along in a second terminal)
natsgothe bus server itself, built from source — components/nats compiles the official nats-server into var/bin/nats-server; core prefers that binary over a PATH install, so make build alone satisfies the bus dependency, and the bundled build runs with an 8 MiB payload cap (upstream default 1 MiB) so whole-conversation LLM requests fit; a PATH fallback gets the same 8 MiB cap via a config file (core warns once on fallback), and core checks the attached bus's max payload at boot, warning loudly instead of failing mid-conversation
uigo + svelte 5the desktop chat UI — sessions, streaming tokens, tool runs, approvals, model controls · Wails-hosted SPA, architecturally a NATS client
your toolanyport the SDK — the envelope is the artifact (~200 lines)
