A self-extending agent harness

Simple and fast harness.
Batteries included.

Niffler is built from small Unix-style processes — every capability is a component on one NATS wire — so the agent can write, compile and spawn its own tools mid-conversation.

Niffler is as simple and efficient to drive as the leanest coding agents — cache-stable prompts, a tiny toolset, measured low token use. Sub-agents, background processes, a permission gate, MCP, LSP? In the box as well.

01 Fast & cache-effective

Strict cache regime,
token efficient.

The request prefix is tiny and stays byte-stable for the conversation's lifetime: a very small base prompt and a deliberately small frozen direct toolset, so provider caches stay hot turn after turn. Everything else is progressive discovery — one discover/invoke away, entering as history instead of prompt bloat. Fewer tokens per turn, quicker round trips — and the numbers are measured in bench/ against pi, opencode and claudecode, not asserted.

cache hit · 250.3k new this turn · 1.8k 99.3% — printed in the UI, every turn

What this measures. Numbers gathered with DeepSeek‑V4.1‑Flash (deepseek-v4-flash) at low thinking effort, called directly through DeepSeek's first‑party API — no gateway, no proxy; the same key and endpoint for every harness. The tasks are deliberately simple, well‑specified coding exercises: this is not a capability benchmark. It measures the three things that dominate real daily cost — tokens per task, wall‑clock per task, and price per task — for normal work.

02 Interesting features, relatively rare

Not one of a kind —
rarely all together.

None of the following is exclusive to Niffler. But the lean harnesses make you give most of it up, and the big ones hide it behind their UI. Here it is all in one small box:

Sub-agents

Delegate and walk away — a background child job runs, and when it settles it wakes your conversation with the result. Steer, continue or fork it later.

Background processes

Servers, watchers and builds run under the harness: start, poll, kill. No second terminal, no tmux discipline.

Permission gate

A tool can ask first. You answer y/N per call — sub-agents included: their gated calls route to you, their budgets are hard-wired. With no human reachable, the call is denied. Fail closed, never silently allowed.

Self-extension

The agent writes a source file, compiles it, spawns it as a process and calls the new tool — mid-conversation, in any language. Community packages install the same way, always built from source.

Programmable tool calling

fabric compiles a small guest program the agent writes: typed wrappers over pinned tool schemas turn a dozen tool calls into one native loop — effect-aware batching, budgets, approvals by content digest.

Compaction as a projection

Context pressure walks a visible ladder — byte-exact prune, then a checkpointed projection compactor (a replaceable seam), then trim as a last resort. Nothing degrades silently, a trim is durable, and everything dropped stays recallable.

One conversation = one process

Each conversation gets its own session runner, so conversations run truly in parallel and one dead runner loses only its in-flight turn. An advisory peer (expert) can watch a session and advise — turn-bound, never steering by itself.

Any language

Components are plain processes: Nim, Go, TypeScript — or a shell script with no SDK at all. The language is a preference.

03 Everything you take for granted

The table stakes,
all of them.

None of this is exotic — you expect it in a serious harness. Some minimal ones make you give it up. Niffler ships all of it:

Providers, no JSON

Add a backend with one call and hop with /model and /effort — no config files to hand-edit. OpenAI-compatible, Anthropic and Codex lanes, or log in with your ChatGPT/Claude subscription over OAuth. Pins are per-conversation.

MCP in, tools out

Register any MCP server once (stdio, http or sse): a supervised bridge process per server announces its tools and prompts as ordinary catalog tools — same discovery, same approval gate, same call path.

LSP for your language

Diagnostics, definitions, references, hover over real language servers: Go, Nim, TypeScript/JavaScript, Python, Rust, C/C++, Bash, Java, PHP, Ruby, C# ship configured. Yours missing? One entry in servers.json — the agent can add it itself.

Code, files & the web

  • File toolsbatched windowed reads, exact-match edit with a guarded fallback, atomic write, persistent undo
  • Searchgitignore-aware grep and file finding — stateless replicas so parallel calls really run in parallel
  • Gitstatus, diff, log, show, blame — read-only and approval-free
  • Web fetchreal HTML extraction, SSRF-validated, oversized bodies spill to disk
  • Imagesscreenshot in, multimodal turn out — MIME checks, caps and pixel budgets included
  • Repo mapranked symbols auto-appended where a repo earns it

Conversations & context

  • Steeringcourse-correct mid-turn without cancelling the work in flight
  • Full recalltrimmed or compacted-away messages stay searchable through context_recall
  • Durable resumecanonical append-only history in the store — restart mid-task and continue, attachments included
  • Per-conversation controlstool allowlists, budgets, workspace pin, provider/model/effort pins
  • Introspection/export the exact provider request, prompt_preview, per-role counts, /compact now
  • Slash commandsbuilt in — plus ones contributed by installed plugins and MCP servers

Trust & safety

  • Approvals everywhereany gated caller, sub-agents included — routed to the human driving the turn, denied when none is reachable
  • Sub-agent limitshard budgets that cannot be talked around; soft limits negotiate over the approval channel
  • Remembered grantsper-tool “don't ask again”, digest-keyed for program-shaped calls
  • Fail closedtimeouts deny, unknown limits refuse, a missing component degrades explicitly — never silently
  • Least privilegeMCP environment allowlists and guard processes, no bus access or secrets in fabric's executor, redacted listings

Ecosystem & extension

  • Agent SkillsSKILL.md skills: list, search, install and audit — interop with the wider skills ecosystem
  • PluginsGitHub packages cloned and built from source, approval-gated, manifest v1 or v2 recipes
  • Three SDKsNim, Go and TypeScript around one tiny portable codec — or no SDK at all, a shell script speaks the wire
  • Tool profilesnamed toolset selectors resolved once per conversation, or sticky tools promoted on demand
  • A store that answersserver-side full-text search; SQLite or TiDB behind one contract

04 Clients, not containers

The harness
isn't a UI.

Niffler runs headless as a shared local service: the agent, its tools, background jobs and history live in the instance — not in a window. Clients are thin attachers over the bus; several can share one running instance at once. A client boots the harness on demand, an autostarted core turns itself off when the last client leaves — and closing your terminal mid-task loses nothing: background jobs keep running and wake the conversation when they settle.

  • niffler-tuithe terminal chat client — a plugin that boots the harness on demand
  • clithe headless driver: call tools, install packages, run whole turns from a script or CI
  • consolesubscribes the bus and renders every envelope live — better than nats sub
  • desktop UIan experimental spin-off package (gokr/niffler-ui) — same wire, its own repo

Service mode runs with no terminal at all (niffler < /dev/null) — and niffler in a terminal is an admin shell (status, catalog, sessions), not a chat.

05 Unix-style architecture

Small programs,
one wire.

Every capability is a separate process that does one thing — its own lifecycle, its own failures, isolated from the agent's mind. One wire connects them all: JSON envelopes over NATS. So the agent can write, compile and spawn a new tool mid-conversation, and teardown is just exit(). The OS is the disposer.

envelope.json
{
  "v": 1,
  "id": "1760825…-4242-1",
  "kind": "call",
  "tool": "bash",
  "args": { "command": "uname -a" },
  "caller": "cli"
}

Calls land on svc.<component>.call (core serves svc.core.call), events fan out on ev.* — four kinds: call · result · event · error. That is the whole bus contract.

The codec is ~77 lines of pure std/json, mirrored 1:1 by the Nim, Go and TypeScript SDKs — spec: docs/WIRE.md · rationale: research/REBOOT.md

06 Sources of inspiration

Credit where
credit is due.

Niffler is meant to be easily extended — a trait it shares with Pi, its biggest influence. It wears its sources on its sleeve. What we took, and from where:

Pi

Token efficiency, a small initial toolset and self-aware extendability — a harness meant to be easily extended. Niffler is built the same way and pushes a variant architecture: loosely coupled components, replaceable at runtime.

DSH

The more advanced component model, and the serious techniques most harnesses never attempt: projection-based compaction and the sub-agent model.

Opencode

Simplicity of use — the standing reminder that a powerful harness can still be obvious to drive.

Reasonix

The strict cache regime, working especially well for models with cheap cached tokens like DeepSeek — where cache hits are the economics of the turn.

07 Install

Two minutes in.

terminal 
curl -fsSL https://raw.githubusercontent.com/gokr/niffler/main/scripts/bootstrap.sh | bash
# asks: stable release or main, and where to create ~/niffler (or | bash -s -- /your/dir)
# or manually, from a clone:
git clone https://github.com/gokr/niffler.git && cd niffler
make setup && make build
cp .env.example .env   # add a model API key
make install-tui       # the terminal client (a plugin)
niffler-tui            # boots the harness on demand
  • ✓ nim 2.2.12+
  • ✓ go
  • ✓ node / npm — optional: npx skills, npm MCP servers, TypeScript components (the core, clients and the TUI are Nim/Go — the installer asks)
  • ✓ trafilatura — optional, richer HTML extraction

Niffler is built from source and distributed that way — there are no prebuilt binaries. The one-line installer brings in everything missing (git, make, curl, Go, then the Nim toolchain and nimble packages via make setup); Node.js and npm are optional and it asks first. Building by hand, make doctor reports what is missing. The bus is bundled — core spawns its own nats-server. The desktop UI is an experimental spin-off — install it like any package: cli install gokr/niffler-ui. Full story in the manual ↗.

Small by default. It builds the rest.
